# TR/EN language structure (NFR-10, 23 Nov 2026)

Owner: Onur (#58). One language system for the whole frontend; do not add a
second one. Turkish is the default; the header button (EN/TR) switches the
language and the choice is kept in `localStorage["smartloo.lang"]`.
Switching re-renders text only: session, filters, the selected facility and
form input are kept. `<html lang>` follows the language.

## How to translate a screen

```jsx
import { useI18n } from "../../shared/i18n/I18nProvider.jsx";

function ReviewList({ reviews }) {
  const { t, locale } = useI18n();
  return (
    <section aria-label={t("Yorumlar")}>
      <h2>{t("Yorumlar")}</h2>
      <p>{t("{n} değerlendirme", { n: reviews.length })}</p>
      <time>{new Date(reviews[0].created_at).toLocaleDateString(locale)}</time>
    </section>
  );
}
```

1. Wrap the Turkish text in `t(...)`. The Turkish text is the key. Put changing
   parts in `{placeholders}`; do not build sentences with `+` or template strings.
2. Add the English text to
   [`frontend/src/shared/i18n/en.js`](../../frontend/src/shared/i18n/en.js)
   under your screen's section. A missing entry shows Turkish, so nothing breaks.
3. Messages returned by helper functions (error texts etc.) stay Turkish in the
   helper; translate where they are shown: `{t(errorMessage)}`.
4. Format numbers and dates with `locale` from `useI18n()` (`tr-TR` / `en-GB`).
5. Add your folder to `TRANSLATED` in `frontend/src/shared/i18n/i18n.test.jsx`;
   the test then fails for any `t("…")` without an English entry.

Without a provider (isolated component tests) `useI18n()` returns Turkish, so
existing tests that check Turkish text keep working.
